Table meta config: a field guide to every cell type

The one config object that decides how every column of a report table renders — status pills, links, dates, nested objects, images, and action buttons. Verified directly against source, with a working JSON example for every field.

Verified against types/tables.d.ts, types/action-button.d.ts, configs/sidebar.tsx Scope report-table cell rendering (TableMeta) Last updated 2026-09-25
actionButtons (§6) is spec-verified, not yet field-verified in a live report

Read first: a naming collision that will confuse you otherwise

Gotcha

A sidebar report node's config object has a table key holding the whole meta object documented here (TableMeta) — and TableMeta itself has a table key further down that means something completely different: “render this column as a nested/expandable sub-table.” Two unrelated concepts share the same name, one nested inside the other. config.table.table is not a typo — it's TableMeta.table (§2, nested-object rendering) sitting inside config.table (the whole meta object). Keep this straight when reading or writing config.

End-to-end flow: authored as part of a sidebar node's config.table (configs/sidebar.tsx, or the equivalent Cosmos-backed sidebar document in production) → delivered to the client as ReportProps.config (components/ui/table/index.tsx) → read column-by-column in TableCellRenderer (components/ui/table/cell/index.tsx), which dispatches on colname against each array below to decide how that cell renders. One field — actionButtons (§6) — doesn't key off colname at all: it renders as one synthetic trailing _actions column for the whole row, the same pattern the built-in row-selection checkbox column (_selection) already uses.

00

Column basics

pagination, paginationMode, sortable, align, and hidden — the fields that shape the table shell rather than any one cell.

TableMeta (partial)
{
  "pagination": true,
  // "offset" (numbered pager, default) or "cursor" (prev/next + continuation
  // token) — "cursor" only takes effect when the report's source type is
  // COSMOS; the server rejects it for anything else.
  "paginationMode": "offset",
  "sortable": [
    { "col": ["id"], "order": "desc" },
    "name"  // bare string = sortable, no default order
  ],
  "align": {
    "center": ["id", "status_dot"],
    "end": ["amount"]
  },
  "hidden": ["object", "_uuid"]
}

align keys are "start" | "center" | "end". hidden columns are still fetched but never rendered or toggle-able — different from a column simply not being in the report's columns list.

01

Status rendering

Three visual treatments — dot, tag, chip — driven by the same value-matching config. A column can only be in one of the three lists.

TableMeta.status
{
  "status": {
    "config": {
      "success": ["Success", "Online", "Filled", "Passed", "True", "Open"],
      "failed": ["Failed", "Offline", "Danger", "Blocked", "Not Passed", "False", "Closed"],
      "info": ["Info", "Information"],
      "warning": ["Warning", "Alert", "Partially Filled"],
      // anything outside the four standard buckets gets its own exact hex
      "custom": [
        { "value": ["Rejected"], "hex": "#6d5ae3" }
      ]
    },
    "type": {
      "dot": ["status_dot"],
      "tag": ["status_tag"],
      "chip": ["status_chip"]
    }
  }
}
02

Joined, object, and nested-table cells

joined merges several source columns into one display column with a primary + secondary line. object renders a JSON value as an expandable tree. table (see the naming gotcha above) renders a column as a nested sub-table.

TableMeta (partial)
{
  "joined": [
    { "head": ["name"], "sub": ["email", "normal"], "as": "joined" }
  ],
  "object": ["object2"],

  // TableMeta.table — NOT the sidebar node's config.table wrapper.
  "table": ["object_render"],
  // shorthand: a lone entry is a one-element array
  // "table": "object_render",
  // per-column depth override:
  // "table": [{ "column": "object_render", "maxDepth": 3 }],

  // default depth for every `table` column with no own maxDepth (fallback 5)
  "tableDefaultMaxDepth": 5,

  "truncate": ["object"]
}
03

Link cells

redirect/color accept either one fixed value, or an array of MatchedRule objects evaluated against the cell's own value — first match wins.

TableMeta.link[]
{
  "link": [
    {
      "columns": ["Link"],
      "config": {
        "url": "https://dummyjson.com/auth/login",
        "method": "POST",
        "headers": { "Content-Type": "application/json" },
        "body": "{\"username\":\"emilys\",\"password\":\"emilyspass\",\"expiresInMins\":30}",
        "credentials": "include",
        "style": "plain",
        "redirect": [
          { "value": "e", "style": "contain", "match": "broad", "redirectOption": "external" }
        ],
        "color": [
          { "value": "e", "style": "contain", "match": "broad", "colorOption": "success" },
          { "value": "r", "colorOption": "danger" }
        ]
      }
    }
  ]
}
FieldValid values
redirectOptionexternal · internal · window
colorOptionsuccess · warning · foreground · primary · secondary · danger
rule styleexac · startWith · endWith · contain
rule matchexac · broad · phrase

colorOption uses the same six-color palette (LinkColor in components/ui/link/core.tsx) that action buttons use in §6 — one palette, reused everywhere in the app rather than redefined per feature. TableMetaLinkConfig also has a [key: string]: any escape hatch: credentials above isn't a named field, just passed through.

04

Date / time cells

TableMeta.date[]
{
  "date": [
    {
      "columns": ["date2"],
      "type": "datetime",
      "format": "DD/MM/YYYY HH:mm:ss",
      "timezoneConfig": {
        "enableToggle": true,
        "defaultView": "utc",
        "localTimezone": "Asia/Bangkok",
        "tabLabels": { "utc": "UTC", "local": "BKK" }
      },
      "constraints": {
        "minDate": "today",
        "disableWeekends": true
      },
      "pickerProps": {
        "allowClear": false,
        "showNow": true,
        "placement": "bottomRight"
      },
      "readOnly": true,
      "granularity": "minute",
      "hourCycle": "24-hour"
    }
  ]
}

type is date | time | datetime (default datetime). constraints.minDate/maxDate accept an ISO string or the literal "today". pickerProps is a raw passthrough to the underlying date picker — treat anything not shown here as unverified.

05

Image, truncate, disabled

Three plain string[] fields, no nested config.

TableMeta (partial)
{
  "image": ["avatar_url"],
  "truncate": ["_uuid", "userAgent"],
  "disabled": ["bank", "_uuid"]
}

disabled removes the column from columnDef entirely (not just hidden). truncate clips long text with an ellipsis. image renders through the app's image proxy (next/image + app/api/image-proxy) instead of as text.

06

Action buttons

Full design source of truth: notes/trash/2026-09-24-optional-button-plan-v8.md and types/action-button.d.ts. Unlike every field above, actionButtons doesn't key off colname — it renders as one trailing _actions column for the whole row.

Core rules
  • roles on a button is visibility only. The server independently re-checks roles against the resolved alias entry before executing anything — a visible button is never itself an authorization decision.
  • actionRef is always an opaque id. No pipeline name, endpoint URL, or credential ever appears client-side — those resolve server-side, one hop, from one of three per-service alias documents (adf_alias_config, azf_alias_config, external_api_alias_config).
  • execute_api is for genuinely external, third-party APIs only. Anything this project itself builds is azure_function — Azure Functions is the project's primary API mechanism.

redirect — client-only navigation

{
  "id": "btn-portal",
  "actionType": "redirect",
  "title": "Open Portal",
  "roles": ["user", "admin"],
  "url": "https://example.com/",
  "target": "_blank",
  "style": { "variant": "secondary", "fontWeight": "bold" },
  "icon": { "name": "external", "position": "right" }
}

target is _self | _blank only — no popups, no _parent/_top. _blank always applies noopener,noreferrer.

adf_pipeline — Azure Data Factory

{
  "id": "btn-run-pipeline",
  "actionType": "adf_pipeline",
  "title": "Run ADF Pipeline",
  "roles": ["admin", "data_engineer"],
  "actionRef": "callpipelist-prod",
  "parameters": {
    "recordId": { "fromRow": "id" },
    "updatedBy": { "fromUser": "id" },
    "environment": "production"
  },
  "refreshTableOnSuccess": true,
  "feedback": {
    "successMessage": "Pipeline triggered successfully.",
    "errorMessage": "Could not trigger the pipeline."
  },
  "style": { "variant": "primary", "fontWeight": "semibold" },
  "icon": { "name": "play", "position": "left" }
}

Resolves directly into adf_alias_config. Not testable against a local emulator — verified against a real Data Factory (QA tenant or above).

azure_function — this project's own APIs

{
  "id": "btn-recalc-billing",
  "actionType": "azure_function",
  "title": "Recalculate Billing",
  "roles": ["admin", "billing_ops"],
  "actionRef": "azf-recalc-billing",
  "payload": { "invoiceId": { "fromRow": "id" } },
  "refreshTableOnSuccess": true,
  "style": { "variant": "primary" },
  "icon": { "name": "zap", "position": "left" }
}

authMode on the resolved alias entry is function_key | azure_ad_token | managed_identity | none — token-based today, Managed Identity is a config-only cutover once provisioned.

execute_api — genuinely external APIs only

{
  "id": "btn-fetch-carts",
  "actionType": "execute_api",
  "title": "Fetch Cart Data",
  "roles": "admin",
  "actionRef": "carts-lookup",
  "payload": { "collectionName": "carts" },
  "style": { "variant": "success" },
  "icon": { "name": "grid", "position": "left" }
}

Resolves into external_api_alias_config. The outbound host must be present in REPORTS_ALLOWED_HOSTS — the same allowlist reports' own API-type source already enforces.

custom_callback — in-app, client-only

{
  "id": "btn-refresh",
  "actionType": "custom_callback",
  "title": "Refresh Table",
  "handlerName": "refreshTable",
  "style": { "variant": "foreground", "iconOnly": true },
  "icon": { "name": "arrow" },
  "ariaLabel": "Refresh table"
}

handlerName resolves through a fixed, closed client-side registry — never an open string-to-function lookup. No server round trip.

Destructive action — confirm

Always required 
{
  "id": "btn-delete-collection",
  "actionType": "azure_function",
  "title": "Delete Collection",
  "roles": ["super_admin"],
  "actionRef": "azf-collection-delete",
  "payload": { "collectionId": { "fromRow": "id" } },
  "confirm": { "message": "This permanently deletes the collection. Continue?" },
  "refreshTableOnSuccess": true,
  "style": { "variant": "danger", "fontWeight": "bold" },
  "icon": { "name": "trash", "position": "left" }
}

Full combined example

Every feature above, in one TableMeta object — extends the real config already shipping in configs/sidebar.tsx with an actionButtons array.

config.table (full)
{
  "pagination": true,
  "sortable": [{ "col": ["id"], "order": "desc" }],
  "align": { "center": ["id"] },
  "joined": [{ "head": ["name"], "sub": ["email", "normal"], "as": "joined" }],
  "truncate": ["object"],
  "status": {
    "config": {
      "success": ["Success", "Online"],
      "failed": ["Failed", "Offline"],
      "info": ["Info"],
      "warning": ["Warning"],
      "custom": [{ "value": ["Rejected"], "hex": "#6d5ae3" }]
    },
    "type": { "dot": ["status_dot"], "tag": ["status_tag"], "chip": ["status_chip"] }
  },
  "link": [
    {
      "columns": ["Link"],
      "config": {
        "url": "https://dummyjson.com/auth/login",
        "method": "POST",
        "redirect": "external",
        "color": "primary",
        "style": "plain"
      }
    }
  ],
  "object": ["object2"],
  "table": ["object_render"],
  "hidden": ["object"],
  "date": [
    { "columns": ["date2"], "type": "datetime", "format": "DD/MM/YYYY HH:mm:ss" }

      "id": "btn-azf-recalc",
